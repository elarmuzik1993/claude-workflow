Merge one PR: the most recently opened open PR whose head is the current branch, opening one
first if there's none. Running this is the request to commit, push, open and merge it. Say
which PR you'll merge before committing.

Arguments: $ARGUMENTS
A PR number or branch: use that one instead of the current branch. On the main branch with
nothing named, list my open PRs and ask which.

## Behavior
1. **Commit and push** as `/workflow:handoff` steps 5–6 do (rename a generated branch name
   first; open the PR if the branch has none). Only when the PR is a named one on another
   branch, stop instead of committing. A PR not opened by me: show it and ask before going on
2. **Gate:** the PR is ready (not draft), has no conflicts and no unresolved "changes
   requested". Verify is not run here: the plugin's merge gate runs the repo's verify on the
   PR's head commit, so pass it as `expectedHeadSha`. If the gate or the hook blocks, don't
   merge and don't force: say what blocks it
3. **Clean the description:** remove any line a tool added that credits a model, agent or
   session (such as a "Generated by" footer or a session link)
4. **Merge** with the repo's usual method: a merge commit unless `git log` on the main branch
   shows squash merges. The merge message carries no AI attribution
5. **Afterwards:** `git fetch --prune origin`, switch to the main branch and fast-forward it
   (`git pull --ff-only`), then delete the merged branch locally (`git branch -d`) and on the
   remote (`git push origin --delete <branch>`). If the remote refuses, say so; the local
   deletion stands
6. **Publish the mirror,** in the dotfiles repo only: `bash scripts/publish-mirror.sh`, and
   report its line (nothing printed means the mirror was already current)

## Output format
- **Merged:** PR number and title, link, the merge commit, the method, the branch deleted
- or **Not merged:** the PR and the one thing blocking it, plus what would unblock it
- **Now on:** the branch you're on afterwards
- **State note:** only in a repo with `.agents/STATE.md` that the merged branch didn't change:
  say it is now behind, and that `/workflow:handoff` updates it

## Constraints
- Do NOT merge more than one PR
- Do NOT use admin override, skip a check, or force-push to make it merge
- Do NOT rebase or edit the PR's branch to fix conflicts without asking
- Do NOT write merge or PR status into `.agents/STATE.md`

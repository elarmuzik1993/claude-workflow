Compare what we're discussing with similar projects that already exist, so I can see where it
stands and what to borrow. Read only: don't change any files.

What to compare: $ARGUMENTS
If that's empty, use the main topic or project of this conversation. If there's no clear
subject, ask what to compare.

## Behavior
1. **Pin down the subject:** one line on what it is and what it does, from this conversation
   and the repo
2. **Find 3 to 5 comparable projects** with a web search: open-source repos, products, or
   well-known approaches to the same problem. Prefer ones that are maintained and widely used
3. **Compare on what matters for this subject:** the dimensions I named, or else purpose,
   approach, scope, maturity and adoption, ease of use, and cost or licence
4. **Judge it:** where ours is ahead, where it's behind, and what is genuinely unusual about it
5. **Borrow:** up to 3 concrete ideas worth taking from the others

## Output format
- **Subject:** one line
- **Compared with:** a table, one row per project (ours first), one column per dimension,
  each project's name linked to its source
- **Where ours stands:** ahead, behind, unusual; up to 2 bullets each
- **Worth borrowing:** up to 3 bullets
- **Verdict:** one sentence

## Constraints
- Do NOT put private details in search queries: no private repo or project names, paths,
  emails or tokens. Describe the subject in general terms instead
- Do NOT state facts about a project you didn't check this session; link each one's source
- Do NOT pad the list with weak matches; fewer good comparisons beat five loose ones
- Do NOT change files or start work on the ideas; wait for my choice

You are in CHALLENGE mode. Your job is to find what's wrong with an idea before I commit to it.

The idea: $ARGUMENTS
If that's empty, challenge the latest plan or proposal in this conversation, yours included, and
say which one. If there's none, ask what to challenge.

## Behavior
- Restate the idea in one line first, so we agree on what's being tested
- Attack it where it matters: hidden assumptions, how it fails, what it costs to build and keep,
  what it rules out later, and whether something simpler does the job
- Check claims against the code and docs when you can, rather than arguing in the abstract
- Rank objections by how much they'd hurt. A few serious ones beat a long list
- Be honest: if the idea holds up, say so. Don't invent objections to fill the format

## Output format
1. **The idea** — one line
2. **Objections** — most serious first, each with why it matters and what would answer it
3. **Simpler alternative** — only if one exists
4. **Verdict** — Go / Go with changes / Rethink, in one line
5. **Answer first** — the one question to settle before starting

## Constraints
- Do NOT edit files or start building
- Do NOT soften objections into compliments, or pad them with minor style points
- This applies to this reply only: after it, work as you normally would

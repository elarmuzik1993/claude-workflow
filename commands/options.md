Before doing anything, give me 2 or 3 real ways to do this and let me choose.

The task: $ARGUMENTS
If that's empty, use the task we're about to start in this conversation. If there's none, ask
what I want to do.

## Behavior
- Look at the code first, so each option fits how this repo already works
- Make the options genuinely different, not one idea in three sizes
- Include the smallest option that would do the job, even if it's "change nothing"
- Be concrete: what each one changes, roughly how big it is, and what it rules out later
- If there's really only one sensible way, say so and why, instead of inventing alternatives

## Output format
### Option A: <short name>
- **What:** one or two lines
- **Pros / Cons:** a few words each
- **Size:** small / medium / large

(same for B and C)

### Recommendation
Which one and why, in one or two lines.

## Constraints
- Do NOT edit files or start building until I pick one
- Ask any question that would change the choice, instead of assuming the answer
- This applies to this reply only: once I pick, work as you normally would
